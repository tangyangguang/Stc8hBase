# STC8H8K64U PWMB 正交编码器 HAL 设计

## 1. 背景与准入结论

`farm-auto-modbus` 的单电机分站需要对霍尔 AB 相增量编码器做持续计数。当前板级方案把电机双 PWM 放在 `PWMA3/PWMA4`，把编码器 A/B 放在 `P2.0/PWMB5/TI5` 与 `P2.1/PWMB6/TI6`。现有 GPIO、EXTI 和 Timer HAL 可以组合出软件边沿计数，但会占用中断和 CPU，且不能替代芯片已有的硬件正交解码。

因此新增一个薄 QEI HAL 是真实、可复用的基础库缺口。第一版只覆盖当前已经确认和能够构建验证的 `STC8H8K64U` `PWMB` 编码器计数，不扩展为通用电机、位置控制或编码器驱动框架。

## 2. 官方依据

依据仓库内 `docs/vendor/stc/STC8H-en.pdf`：

- 20.7.5：`PWMB_SMCR.SMSB=001/010/011` 分别为 encoder mode 1/2/3；mode 3 在 `TI5FP5` 和 `TI6FP6` 的边沿上根据另一输入电平增减计数。
- 20.7.11、20.7.12：`PWMB_CCMR1/2` 把通道 5/6 配置为 `TI5FP5/TI6FP6` 输入，并提供 1、2、4、8…256 个时钟的数字滤波编码。
- 20.7.15：`PWMB_CCER1` 的 `CC5E/CC6E` 使能两个输入，`CC5P/CC6P` 选择输入极性。
- 20.7.17、20.7.18：`PWMB_CNTRH/CNTRL` 是共享的 16 位计数器。
- 20.8.3：官方正交编码器示例采用输入模式、数字滤波、encoder mode 3 和计数器使能顺序。

本设计只吸收已核实的寄存器事实，不照搬官方示例中的中断和捕获读取逻辑。

## 3. 第一版范围

提供：

- 编译期选择 `TI5`、`TI6` 引脚复用组。
- 编译期选择 encoder mode 1/2/3。
- 编译期选择输入数字滤波编码。
- 初始化并启动 `PWMB` 16 位硬件正交计数器。
- 无中断地读取稳定的 16 位原始计数。
- 显式停止并释放 `PWMB` 计数输入。

不提供：

- 电机方向、速度环、位置环、回零、限位或故障策略。
- 32 位/64 位软件累计位置、速度窗口或单位换算。
- 编码器 PPR、减速比、x1/x2/x4 产品语义。
- 中断回调、溢出 ISR、隐藏全局状态或动态资源管理。
- 与 PWM HAL 同时共享 `PWMB`。
- `PWMA` QEI、其他 STC 型号或未验证引脚封装的泛化支持。

## 4. 配置与 API

配置从 `core/stc8h_config.h` 的既有入口进入，模块头文件要求调用方显式给出：

```c
#define STC8H_QEI_PWMB_TI5_PIN_SELECT 0u
#define STC8H_QEI_PWMB_TI6_PIN_SELECT 0u
#define STC8H_QEI_PWMB_MODE           3u
#define STC8H_QEI_PWMB_FILTER         2u
```

其中 `FILTER=2` 对应官方表中的 4 个采样时钟。以上数值只表示 MCU 外设配置；例如 `pin_select=0` 是否对应目标 PCB 的 `P2.0/P2.1`，必须由板级引脚表确认。

第一版 API：

```c
void stc8h_qei_pwmb_init(void);
stc8h_u16 stc8h_qei_pwmb_read(void);
void stc8h_qei_pwmb_stop(void);
```

约束：

- `init()` 从 0 初始化计数器并立即开始计数。
- `read()` 只返回模 `65536` 的硬件原始值，不解释方向和机械单位。
- `stop()` 停止计数、关闭通道 5/6 输入和 encoder mode；不替调用方重配 GPIO 电气模式。
- 调用方必须先把实际 A/B 引脚配置为适合电气接口的数字输入；上拉、串阻和 RC 属于板级设计。
- 若应用用相邻读数之差累计位置，两次读取之间的真实净变化绝对值必须小于 32768 counts，才能无歧义地用 16 位回绕差解释方向。

## 5. 寄存器初始化顺序

`init()` 按以下顺序独占配置 `PWMB`：

1. 打开 XFR 访问。
2. 停止 `PWMB` 计数器，关闭 `PWMB_ENO` 输出和 `PWMB` 中断。
3. 先清 `SMCR.SMSB` 和 `CC5E/CC6E`，再修改输入映射。
4. 在 `PWMB_PS` 中只改通道 5/6 的复用选择位。
5. 把 `CCMR1/2` 配为直接 TI 输入、无输入预分频和指定数字滤波。
6. 配置非反相 `CC5P/CC6P`，使能 `CC5E/CC6E`。
7. 设置预分频为 0、自动重装为 `0xFFFF`，通过更新事件把计数器清零。
8. 设置 encoder mode，最后置位 `CR1.CENB`。

`read()` 使用 high-low-high 重读，避免计数器恰好跨越低字节边界时拼出撕裂值。模块不启用 ISR，也不保留 RAM shadow。

## 6. 资源与冲突

启用本模块时占用：

- `PWMB` 整个 16 位计数器。
- `PWMB` 通道 5/6 输入。
- 两个由编译期复用值选定的 TI5/TI6 引脚。

不占用：

- 中断向量。
- Timer0/1/2/3/4。
- 固定 RAM 或全局缓冲。
- `PWMA`，因此当前板仍可把 `PWMA3/PWMA4` 用于电机双 PWM。

`PWMB` 的通道 5..8 共用计数器、周期和模式，所以 QEI 与任何 `PWMB` PWM 输出互斥。第一版不引入资源管理器；应用和板级构建必须保证不同时编译/调用冲突配置。

未编译 `hal/stc8h_qei.c` 时，模块对 ROM、RAM、外设和初始化均为零占用。

## 7. 验证门槛

无硬件阶段：

- 新增一个只编译 QEI HAL 和最小主程序的 `STC8H8K64U` PlatformIO 示例。
- `pio run` 通过，并记录 ROM/RAM、参与编译文件和无中断结论。
- `tools/prepare_h8k64u_validation.sh` 和适用的完整检查通过。
- 在不引用 QEI 的代表性示例 map 中确认不存在 QEI 符号。

硬件阶段：

- P2.0/P2.1 输入静止时计数稳定。
- 正反转时原始计数方向相反，跨 `0xFFFF/0x0000` 的回绕差正确。
- mode 3 的实际每圈计数倍率与具体编码器实测一致；在实测前不得把它宣称为已冻结的 x4 产品倍率。
- 在计划最高转速下无漏计、乱向或滤波失真。

硬件倍率、最高输入频率和保护阈值不属于本 HAL 的编译验收结论，必须由具体板和真实编码器台架冻结。
